# V1.7 PLC / Physical Reject

## Purpose

V1.7 defines the vendor-neutral boundary from a final inspection decision to a physical PLC/reject action.

## Contract

- `PASS` does not issue a reject command.
- `NG` issues exactly one `PLCCommand` for the inspection.
- Missing `product_id` or `inspection_id` blocks the command.
- PLC transport exceptions become `FAILED`.
- When an acknowledgement callback is configured, `NG` is accepted only after acknowledgement within `ack_timeout_ms`.
- A missing acknowledgement is `TIMEOUT` and is **not** considered successful reject execution.

## Physical commissioning evidence

Before production use, record:

1. PLC connection/health state.
2. PLC command timestamp and inspection ID.
3. PLC acknowledgement timestamp and latency.
4. Physical reject actuator response.
5. One known-PASS product with no reject.
6. One known-NG product with verified physical reject.
7. Repeated NG tests proving no duplicate reject for one inspection.
8. Reject timing from camera/decision to actuator.

Vendor SDK/protocol details remain inside the PLC adapter. The inspection core consumes the vendor-neutral command/result contract.

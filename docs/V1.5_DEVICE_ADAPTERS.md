# V1.5 Device Adapter Contract

V1.5 defines the boundary between vendor SDKs and the inspection core.

## Required semantics

Every real-device adapter should expose:

- `health()` — current device state; only `READY` is usable for commissioning.
- `capabilities()` — vendor/model/serial and supported functions.
- `self_test()` — non-destructive preflight diagnostic.

The core must not import vendor SDKs. A vendor adapter translates SDK-specific
connect/open/capture/trigger/read/write calls into the common interfaces in
`src/integration/hardware_adapters.py` and the health/capability contract in
`src/integration/device_contract.py`.

## Commissioning rule

`DISCONNECTED`, `DEGRADED`, or `FAULT` must never be interpreted as a healthy
production device. A commissioning run is blocked until every required device
reports `READY` and the configured capabilities are present.

## Vendor implementation

When hardware is selected, add a vendor-specific adapter outside the core
pipeline. Do not add vendor SDK calls to `ProductionInspectionPipeline`, the
Rule Engine, or the Orchestrator.

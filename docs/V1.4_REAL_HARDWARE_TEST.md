# V1.4 Real Hardware Commissioning

This is the first milestone at which the software can be connected to a real inspection cell without changing the inspection core.

## 1. Required hardware

- Industrial camera with hardware/software trigger support.
- Trigger sensor or encoder source that produces a `TriggerEvent` with `product_id`, timestamp and position.
- Lighting controller or camera-controlled light source.
- PLC with a deterministic PASS/NG interface and reject output.
- Physical reject actuator and a safe test mode.
- Real AI model artifacts registered in the model registry.

Vendor SDK code stays outside the core. Implement `HardwareFactory` using the vendor SDK and return `Camera`, `TriggerSource`, `LightingController` and `PLCInterface` adapters. `CallbackCamera`, `CallbackTrigger` and `CallbackPLC` can be used as reference adapters.

## 2. Safety before software test

1. Put the conveyor in manual/jog mode.
2. Disable automatic reject actuation until the guarded reject test is explicitly authorized.
3. Confirm E-stop and machine guarding.
4. Confirm camera trigger cannot create an unsafe actuator command.
5. Confirm PLC is connected to the intended test output, not a production actuator.
6. Record camera-to-reject distance and nominal/min/max conveyor velocity.

## 3. Software preflight

Run the existing commissioning report first:

```bash
python -m src.cli commissioning-report
```

Production configuration must not use `MOCK` camera, trigger or PLC drivers, and real model artifacts must validate successfully.

## 4. Controlled acceptance sequence

Use `RealHardwareCommissioning` with a bounded profile. Recommended first run:

- 10 known-good products.
- Same Product ID/model variant.
- Require all 10 PASS before proceeding.
- Record every PLC command and every inspection audit.
- Do not enable automatic reject yet.

Then run one guarded NG test using `guarded_reject_test()` and verify that the PLC receives `Decision.NG` and the physical reject output operates exactly once.

## 5. Fault injection / negative tests

Run one test for each condition:

- Missing trigger.
- Wrong Product ID.
- Stale frame.
- Frame position mismatch.
- Velocity below minimum.
- Velocity above maximum.
- AI timeout/error.
- Recheck exhaustion.
- Reject window exceeded.
- PLC communication failure.

Every failure must result in a safe NG/no-pass outcome and an audit record. A hardware or communication failure must never be converted to PASS.

## 6. Acceptance evidence

Save the following before declaring physical commissioning complete:

- Rule.cmd hash and model artifact hashes.
- Camera settings and lighting profile.
- Measured trigger-to-frame latency.
- Measured AI P50/P95/P99 latency.
- Measured PLC command latency.
- Measured reject actuator latency.
- Conveyor velocity min/nominal/max.
- Camera-to-reject distance.
- 10+ known-good PASS records.
- At least one controlled NG/reject record for each configured defect class.
- HIL/negative-test results.

The software is **not** production-ready merely because this document exists. Production acceptance requires the physical evidence above.
